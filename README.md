# Онлайн-магазин одежды (покупка, доставка)

Итоговый индивидуальный проект по УП 04.01: клиент на Flutter Web и сервер PocketBase. Покупатель выбирает товары, оформляет заказ и следит за доставкой; менеджер ведёт заказы и доставки; администратор управляет каталогом, пользователями и смотрит статистику.

## Запуск при разработке

1. Сервер. Нужен `pocketbase.exe` версии 0.40.x в папке `pocketbase/` ([загрузка](https://pocketbase.io/docs/)). Первый запуск:

```
cd pocketbase
./pocketbase superuser upsert root@shop.local RootPass#2026
./pocketbase serve --http=127.0.0.1:8090
```

Панель администратора: http://127.0.0.1:8090/_/, API: http://127.0.0.1:8090/api/.

2. Схема и тестовые данные (сервер должен работать; нужен Python 3):

```
cd pocketbase/setup
python create_schema.py
python seed.py
```

`create_schema.py` создаёт 12 коллекций с правилами доступа, `seed.py` заполняет их: три роли, каталог из 33 товаров, 36 заказов с доставками. Скрипты можно запускать повторно — данные пересоздаются. Экспорт схемы лежит в `pocketbase/pb_schema.json` (импорт в панели: Settings → Import collections), DDL — в `pocketbase/schema.sql`.

3. Клиент. Адрес API в исходном коде не зашит, его задаёт параметр сборки:

```
flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://127.0.0.1:8090/api
```

Без параметра используется адрес `/api` на том же сайте, откуда загружено приложение.

## Учётные записи

| Роль | Почта | Пароль |
|---|---|---|
| Покупатель | customer@shop.test | Customer#2026 |
| Менеджер | manager@shop.test | Manager#2026 |
| Администратор | admin@shop.test | Admin#2026 |

Новые покупатели регистрируются на экране «Регистрация»; роль `customer` задаётся при регистрации, другую роль назначает только администратор.

## Роли

| Раздел | Покупатель | Менеджер | Администратор |
|---|:-:|:-:|:-:|
| Каталог (просмотр, фильтры) | да | да | да |
| Корзина, оформление, «Мои заказы», «Мои адреса» | да | — | — |
| Заказы (все), позиции заказа, Доставки, Карты лояльности | — | да | — |
| Товары, категории, бренды, коллекции, варианты, способы доставки (изменение) | — | — | да |
| Пользователи и роли, Статистика | — | — | да |

Недоступные разделы скрыты в меню. Если ввести адрес вручную, `redirect` маршрутизатора откроет экран «Недостаточно прав». Решение о доступе к данным принимает сервер: правила коллекций PocketBase заданы в `pocketbase/setup/create_schema.py`, поэтому подмена роли в браузере не даёт прав.

## Архитектура

```
lib/
  core/          конфигурация, Dio и разбор ошибок, права, маршрутизатор, проверки
  models/        модели сущностей и условия выборки ListQuery
  repositories/  интерфейсы репозиториев и реализация для PocketBase (pb/)
  state/         ChangeNotifier: сессия, списки, корзина, справочники, связь с сервером
  entities/      описание сущностей (EntityDef): поля формы, фильтры, колонки
  screens/       общие экраны списка, карточки и формы; экраны магазина
  widgets/       повторно используемые виджеты: таблица, форма, фильтры, пагинация
```

Три общих экрана (`EntityListScreen`, `EntityDetailScreen`, `EntityFormScreen`) строятся по описанию `EntityDef`, поэтому на каждую из двенадцати сущностей не копируется экран. Сервер можно заменить, написав другую реализацию интерфейсов из `repositories/entity_repository.dart`.

Поиск, фильтры (не менее трёх по основным спискам), сортировка и страницы выполняет сервер; условия лежат в адресе: `/products?q=куртка&category=…&size=M&priceFrom=3000&sort=-price&page=2`.

## Адаптивность

| Ширина | Раскладка |
|---|---|
| до 600 px | нижняя навигация, списки карточками, фильтры в блоке «Фильтры» |
| 600–1200 px | боковая полоса навигации, таблицы с основными колонками |
| от 1200 px | развёрнутая навигация, полные таблицы |
| от 1440 px | содержимое ограничено по ширине и центрировано |

Нет связи с сервером: наверху появляется полоса «Нет связи с сервером…», раз в 5 секунд выполняется проверка `GET /api/health`, при возвращении связи упавшие списки перезагружаются сами.

## Проверки и сборка

```
flutter analyze
dart format --set-exit-if-changed lib test
flutter test
flutter build web --release --base-href /clothing_shop/ --dart-define=API_BASE_URL=https://api.example.com/api
cp build/web/index.html build/web/404.html
```

## Публикация

`.github/workflows/deploy.yml` при каждом изменении ветки `main` выполняет анализ, проверку форматирования, тесты и сборку и публикует `build/web` на GitHub Pages. Адрес API задаётся переменной репозитория `API_BASE_URL`; PocketBase при этом нужно развернуть на сервере с доступом по HTTPS.
