# Ответы на типовые вопросы защиты

**Где решается доступность операции и почему там.**
Окончательно — на сервере, в правилах коллекций PocketBase (`pocketbase/setup/create_schema.py`). Клиент только рисует интерфейс: `rolePermissions` в `lib/core/permissions.dart` скрывает кнопки и пункты меню, а `redirect` в `lib/core/router.dart` ведёт на `/forbidden`. Клиентскому коду доверять нельзя: любой запрос можно отправить в обход приложения.

**Что будет при отключении сервера.**
Приложение не падает. `buildDio` (`lib/core/api_client.dart`) превращает сбой сети в `NetworkException`, `ConnectionNotifier` показывает полосу «Нет связи с сервером» и раз в 5 секунд опрашивает `/api/health`. Списки показывают состояние «ошибка» с кнопкой «Повторить», а после возврата связи сами перезагружаются (`restoredCount`). Чтение повторяется до трёх раз, запись не повторяется.

**Подмена данных в DevTools под администратора: почему операция всё равно не выполнится.**
Если в localStorage заменить роль на `admin`, при следующем запуске `AuthNotifier.restore` отправит токен на сервер (`auth-refresh`) и возьмёт роль из ответа. Если не перезагружать страницу и вызвать запрос вручную, сервер проверяет подписанный токен и запись пользователя: правило `@request.auth.role = "admin"` не выполнится, ответ — 400 на создание и 404 на изменение и удаление.

**Прямая ссылка на карточку в новой вкладке.**
`/products/<id>` открывается: на запуске сессия восстанавливается из localStorage, маршрут `:id` читает идентификатор из адреса, `EntityDetailScreen` запрашивает запись у сервера. Без входа ссылка ведёт на `/login?from=…`, после входа открывается нужная страница. Если у роли нет права — экран «Недостаточно прав».

**Граница между слоями, что менять при смене сервера.**
Экраны и состояние знают только интерфейсы из `lib/repositories/entity_repository.dart` и исключения из `lib/core/api_exceptions.dart`. Dio, адреса и формат ответа спрятаны в `lib/repositories/pb/`. При смене сервера пишется новая реализация интерфейсов, собирается другой `ShopDeps` в `lib/main.dart`, меняется разбор ошибки в `mapHttpError`.

**Почему такая связь.**
- 1:1 — `loyalty_cards.user` и `deliveries.order` с уникальным индексом: у пользователя одна карта, у заказа одна доставка.
- 1:N — внешний ключ на стороне «многих» (`products.category`, `orders.user`, `addresses.user`).
- M:N — `collections.products` (список идентификаторов, у связи нет собственных атрибутов) и `order_items` (отдельная сущность, потому что у связи есть атрибуты: количество и цена на момент покупки).

**Обработка ошибки валидации с сервера.**
PocketBase отвечает 400 с `data.<поле>.code`. `mapHttpError` создаёт `ValidationException` с русскими текстами по полям, `EntityForm` (`lib/widgets/entity_form.dart`) показывает текст под полем по имени поля и снимает его, когда пользователь правит поле.

**Самый слабый фрагмент кода.**
Слабым местом было оформление заказа цепочкой запросов без транзакции и с итогом, который считал клиент. Теперь `PbOrderRepository.place` отправляет один `POST /batch`, а остаток и итог считают серверные хуки (`pocketbase/pb_hooks`). Остались: у хуков нет автоматических тестов, токен лежит в localStorage, корзина живёт только в браузере.

**Объяснить любую строку файла.**
Файлы небольшие, у каждого класса есть комментарий. Начинать лучше с `lib/main.dart` → `core/router.dart` → `entities/entity_defs.dart` → `screens/entity/entity_list_screen.dart` → `repositories/pb/pb_repository.dart`.
